### 1. Описание проекта

**WordsLearn** — это интеллектуальное приложение для расширения словарного запаса. Система позволяет пользователям загружать тексты или изображения (с последующим OCR), автоматически извлекать из них начальные формы слов (леммы), обогащать их переводами, транскрипциями и AI-сгенерированными ассоциативными изображениями. Обучение строится на базе пользовательских колод и продвинутого алгоритма интервального повторения (SRS) с поддержкой различных шаблонов тестирования (узнавание, правописание, выбор из вариантов).

### 2. Технологический стек

Для обеспечения масштабируемости, надежности и быстрой доставки функционала выбран следующий стек:

- **Backend Core (Основной API):** NestJS (TypeScript), TypeORM.
- **База данных:** PostgreSQL (реляционное хранение сложных связей словаря и пользователей).
- **Кэширование и сессии:** Redis (хранение refresh-токенов, rate-limiting, временное состояние обучающих сессий).
- **Data Processing Service:** Python + FastAPI (NLP библиотеки spaCy/NLTK, интеграция с Wiktionary, генерация изображений/дистракторов).
- **Frontend:** Next.js + TailwindCSS + shadcn/ui (SSR/SSG для быстрой загрузки, OCR интеграции).

### 3. Архитектурная парадигма (DDD и EDA)

Система спроектирована с расчетом на высокую отказоустойчивость и четкое разделение бизнес-логики.

- **Domain-Driven Design (DDD):**
  Проект разделен на строгие предметные области (Domains), каждая из которых имеет свои границы (Bounded Contexts). Например, `DictionaryModule` ничего не знает об интервальном повторении, а `FolderModule` изолирован от карточек.
  Используется паттерн `Result` (библиотека `neverthrow`) для функциональной и типобезопасной обработки ошибок (RFC 7807 Problem Details), что исключает неконтролируемые исключения (Exceptions). Логика валидации (например, морфология немецкого языка) инкапсулирована в доменные стратегии.
- **Event-Driven Architecture (EDA):**
  Внутри монолита NestJS уже реализована шина событий (Domain Events через `EventEmitter2`), реагирующая на изменения состояния (например, сброс токенов при событии `PASSWORD_CHANGED`).
  Взаимодействие с Python-сервисом спроектировано под асинхронную модель: на этапе MVP используется синхронный HTTP (REST), но архитектура готова к прозрачному переходу на очереди сообщений (RabbitMQ / BullMQ) для тяжелых задач (парсинг текстов, генерация картинок), чтобы не блокировать основной Event Loop.

### 4. Описание сервисов

Архитектура физически разделена на три основных узла:

1. **Backend Core (NestJS):** Центральный узел управления доступом, бизнес-правилами, структурированием учебного контента (Колоды, Папки) и алгоритмом интервального повторения (SRS). Работает с PostgreSQL и Redis.
2. **Data Processing Service (Python):** Изолированный микросервис "тяжелой" обработки. Принимает сырые данные (текст) и возвращает структурированный лингвистический анализ (леммы, части речи), парсит словари и общается с внешними AI-моделями.
3. **Frontend Application (Next.js):** Клиентское приложение, реализующее Data-Driven UI. Управляет состоянием интерфейса, принимает пользовательский ввод (включая загрузку файлов) и отрисовывает учебные карточки на основе шаблонов, полученных от API.

### 5. Детализация модулей системы

#### 5.1 Реализованные модули ядра (Backend Core)

Данные модули уже заложены в фундамент приложения и обеспечивают базовую инфраструктуру:

- **AuthModule & UsersModule:** Управление пользователями, аутентификация (включая Google OAuth), безопасное хранение JWT токенов (с инвалидацией через Redis), защита от CSRF и система ролевого доступа (RBAC: Super, Admin, Manager, Customer).
- **CategoryModule:** Управление глобальными мета-категориями/тегами для классификации контента.
- **DictionaryModule (Глобальный словарь):** Ядро лингвистических данных. Включает сущности `Language`, `Word` (Лемма), `WordMeaning` (Перевод и контекст), `WordForm` (Морфологические формы) и `WordRelation` (Синонимы/Антонимы). Включает продвинутую систему паттерн-валидации (Strategy) для грамматических признаков (напр., немецкие артикли и склонения).
- **UploadModule:** Сервис загрузки и валидации медиафайлов (картинок) на сервер.

Описание типов данных для проектируемых образовательных модулей базируется на стандартах PostgreSQL, обеспечивая масштабируемость и целостность системы. Использование `UUID`, `JSONB` и строгих `ENUM` позволяет гибко управлять контентом, эффективно индексировать связи и поддерживать высокую производительность при сложных запросах.

#### 5.2 Проектируемые образовательные модули (Study Engine)

### 5.2.1 FolderModule (Организация)

Управление папками пользователя. Позволяет группировать учебный контент без влияния на логику обучения. Поддерживает строгую иерархию до 4 уровней вложенности с использованием паттерна Materialized Path.
**Сущность `Folder**` (Хранит метаданные папки и структурные поля для древовидности):

- **`id`**: `UUID` (Primary Key) — Уникальный идентификатор папки.
- **`user_id`**: `UUID` (Foreign Key) — Индексируемое поле для связи с таблицей `users`.
- **`parent_id`**: `UUID` (Foreign Key, Nullable) — Ссылка на родительскую папку (самоссылающийся FK).
- **`depth_level`**: `SMALLINT` — Численное значение (от 1 до 4) для быстрого контроля вложенности без рекурсии.
- **`path`**: `VARCHAR` (или `TEXT`, Materialized Path) — Строка с путями (например, `id1.id2.id3`) для выборки всего поддерева через оператор `LIKE`.
- **`name`**: `VARCHAR(255)` — Название папки.
- **`created_at`**, **`updated_at`**: `TIMESTAMPTZ` — Временные метки с учетом часового пояса.

**Сущность `FolderDeck` (Pivot-таблица)**
(Связующая Pivot-таблица Many-to-Many, позволяющая одной колоде находиться в нескольких папках одновременно):
Логические контейнеры слов. Позволяют пользователю формировать выборки (например, "Слова из фильма X") и делиться ими (паттерн Fork/Клонирование).

- **`folder_id`**: `UUID` (Foreign Key).
- **`deck_id`**: `UUID` (Foreign Key).
- _Ограничение:_ Композитный первичный ключ `PRIMARY KEY (folder_id, deck_id)`.

### 5.2.2 DeckModule (Колоды)

Управление каскадными шаблонами (Cascading Templates) и формирование "фасада" для глобальных слов. Изолирует визуальное представление от бизнес-логики SRS.
**Сущность `Deck**`

- **`id`**: `UUID` (Primary Key).
- **`user_id`**: `UUID` (Foreign Key).
- **`name`**: `VARCHAR(255)` — Название колоды.
- **`description`**: `TEXT` (Nullable) — Детальное описание, без жесткого ограничения длины.
- **`is_public`**: `BOOLEAN` (Default: `false`) — Флаг публичного доступа.
- **`share_token`**: `VARCHAR(32)` (Unique, Nullable) — Короткий хэш для формирования URL (например, `aB3k9P`), проиндексирован для быстрого поиска.
- **`forked_from_id`**: `UUID` (Foreign Key, Nullable) — Ссылка на оригинальную колоду `decks.id`.
- **`created_at`**, **`updated_at`**: `TIMESTAMPTZ`.

### 5.2.3. CardModule (Визуализация)

**Сущность `CardTemplate**`

- **`id`**: `UUID` (Primary Key).
- **`name`**: `VARCHAR(255)`.
- **`front_format`**: `JSONB` — Бинарный JSON для хранения гибкой структуры (например, `{"showImage": true, "showArticle": false}`). Обеспечивает высокую скорость парсинга.
- **`back_format`**: `JSONB`.
- **`target_part_of_speech`**: `ENUM` (Nullable) — Привязка к словарному типу (Noun, Verb, Adjective и т.д.).

**Сущность `UserTemplatePreference` / `DeckTemplatePreference**`

- **`user_id`** / **`deck_id`**: `UUID` (Foreign Key).
- **`part_of_speech`**: `ENUM` — Ключ переопределения (часть речи).
- **`template_id`**: `UUID` (Foreign Key).
- _Ограничение:_ Композитный первичный ключ `PRIMARY KEY (user_id/deck_id, part_of_speech)`.

**Сущность `Card**`

- **`id`**: `UUID` (Primary Key).
- **`user_id`**: `UUID` (Foreign Key).
- **`deck_id`**: `UUID` (Foreign Key, Nullable) — Может быть `NULL`, если карточка находится в глобальном пуле (вне колоды).
- **`word_meaning_id`**: `UUID` (Foreign Key) — Связь с глобальным словарем.
- **`custom_data`**: `JSONB` (Nullable) — Для хранения кастомных мнемоник (например, `{"customImageUrl": "...", "note": "..."}`).
- **`created_at`**, **`updated_at`**: `TIMESTAMPTZ`.

---

### 5.2.4. StudyModule / SrsModule (Алгоритм SRS)

**Сущность `UserCardProgress**`

- **`id`**: `UUID` (Primary Key).
- **`user_id`**: `UUID` (Foreign Key).
- **`card_id`**: `UUID` (Foreign Key).
- **`status`**: `ENUM` — Статусы жизненного цикла: `NEW`, `LEARNING`, `REVIEW`, `MASTERED`.
- **`next_review_date`**: `TIMESTAMPTZ` — Дата и время следующего повторения. Поле требует B-Tree индекса для мгновенного формирования дневной очереди.
- **`interval`**: `INTEGER` — Размер текущего интервала. Обычно измеряется в минутах (для стадии `LEARNING`) или днях (для стадии `REVIEW`).
- **`ease_factor`**: `REAL` (или `DECIMAL(5,2)`) — Коэффициент легкости (множитель) по алгоритму SM-2/FSRS. Значение с плавающей точкой (например, `2.50`).
- **`created_at`**, **`updated_at`**: `TIMESTAMPTZ`.
- _Ограничение:_ Уникальный индекс `UNIQUE (user_id, card_id)`.

## 5.3. FastAPI парсер
